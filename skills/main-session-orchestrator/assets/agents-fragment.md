## Main and stage execution conventions

Main maintains goals, authorization, direction, dispatch, acceptance, and the overview. Executors maintain their stage briefs, runbooks, and handoffs. New projects use `.orchestrator/project.json` and `.orchestrator/stages/`; existing projects retain their explicitly registered ledger entry points.

Read current user decisions, rules, and state before working. Re-read shared files before editing, and change only your owned scope. Submission or process exit is not DONE; completion requires actual artifacts and Main acceptance. Only the user can explicitly resume PAUSED_USER. Check existing owners, receipts, and jobs before dispatch. At stage changes, update purpose, method, findings, limitations, next steps, evidence, and verification time. The web view is a static snapshot.

Merge applicable rules when setting up a project, preserving existing AGENTS instructions. This fragment grants no new authorization.
